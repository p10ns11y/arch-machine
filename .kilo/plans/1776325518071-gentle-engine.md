# AI-Optimized Log Evidence Extraction

## Overview
Refocus from format conversion to **evidence extraction**: Create compact, high-signal "evidence bundles" from maintenance logs for AI agents. Extract structured insights, filter to critical information, and provide actionable context without sending verbose raw logs.

## Key Insights from Analysis
- **Format ≠ Token Savings**: TOON/JSON conversion doesn't reduce tokens unless content is also reduced through extraction/filtering
- **Current Logs**: Security reports are executive summaries (counts, status), not detailed CVE listings; installer.log has extractable errors/warnings
- **Real Value**: Structured evidence bundles with high-signal content (errors, blockers, status changes) vs. raw log processing

## Goals
- **Evidence Extraction**: Parse logs to extract actionable insights (errors, status, blockers, changes)
- **Token Efficiency**: Small, focused JSON bundles instead of full log files
- **AI Context**: Provide "what happened" and "what to do" without overwhelming detail
- **Vector Role**: ETL helper for reliable parsing, not the main solution

## Evidence Sources & Extraction Strategy

### 1. Security Audit Evidence (`logs/security-reports/*.txt`)
**Current**: Executive summaries with tool status, counts, skip reasons
**Patterns Found**:
- Tool status: "OSV-Scanner found vulnerabilities", "Lynis audit skipped - sudo authentication required"
- Metrics: "Total accounts: 30", "Unlocked: 2", "Locked: 28", "Critical: 0"
- Completion: "Success: true", "Report file: [path]"
**Extract**:
- Scan status: completed/partial/skipped
- Tool results: success/failure/vulnerabilities_found
- Blockers: sudo_required, auth_failures, tool_missing
- Metrics: user_counts, service_counts, warning_counts
**Output**: `{"status": "completed", "blockers": ["sudo_required"], "vulnerabilities_found": true, "user_accounts": {"total": 30, "unlocked": 2}}`

### 2. Installer Log Evidence (`logs/installer.log`)
**Current**: Timestamped entries with consistent `[timestamp] [level] message` format
**Patterns Found**:
- Errors: `[ERROR] ❌ Failed to install chkrootkit`
- Warnings: `[WARN] OSV-Scanner not available`, `[WARN] Cannot check listening services`
- Success: `[INFO] ✅ SBOM saved to: sbom.cdx.json`
- Repetitive: Same messages repeat across runs (deduplicate by content + recent timestamp)
**Extract**:
- Unique errors/warnings with timestamps and context
- Tool installation status changes
- Configuration issues (file permissions, service failures)
**Filter**: Only ERROR/WARN, deduplicate identical messages within 24h, limit to last 50 unique issues
**Output**: `{"errors": [{"timestamp": "2026-04-16T11:09:47", "message": "Failed to install chkrootkit", "category": "tool_install"}], "warnings": [...], "unique_count": 15}`

### 3. Weekly Maintenance Evidence (`logs/reports/`)
**Extract**:
- Overall completion status
- Tool execution results
- System health changes
- Compare vs. previous run for deltas
**Output**: `{"status": "completed_with_issues", "tools_executed": ["security_audit", "updates"], "issues_count": 3, "changes_from_last": {"new_warnings": 2}}`

### 4. Update Check Evidence (`logs/update-check-*.json`)
**Current**: Structured JSON with system_packages, tool_updates, security_updates, summary
**Extract**: Parse existing JSON, add comparison with previous update checks
**Output**: Direct JSON enrichment with change detection

## Implementation Plan

### 1. Evidence Extraction Functions (`lib/evidence.sh`)
Create shell-based extractors for reliability and speed:

**`extract_security_evidence(file)`**:
```bash
# Parse security report text files
grep -E "(Status:|Success:|Critical:|Total accounts:|Unlocked:|Locked:)" "$file" |
jq -R -s '{
  status: (match("Status: ([^\n]+)")?.[1] // "unknown"),
  success: (match("Success: (true|false)")?.[1] == "true"),
  critical_issues: (match("Critical: (\d+)")?.[1] | tonumber // 0),
  user_accounts: {
    total: (match("Total accounts: (\d+)")?.[1] | tonumber // 0),
    unlocked: (match("Unlocked: (\d+)")?.[1] | tonumber // 0),
    locked: (match("Locked: (\d+)")?.[1] | tonumber // 0)
  },
  blockers: [
    "sudo_required" | select(match("sudo.*required")),
    "auth_failures" | select(match("authentication.*not available")),
    "tools_missing" | select(match("not available.*profile"))
  ][]
}'
```

**`extract_installer_evidence(file)`**:
```bash
# Extract ERROR/WARN with timestamps, deduplicate
grep -E '^\[([^\]]+)\]\s*\[(ERROR|WARN)\]' "$file" |
sort -u -k3 | tail -50 |  # Deduplicate by message content, limit to 50
jq -R -s 'split("\n") | map(select(. != "")) |
  group_by(match("^\\[([^\\]]+)\\]\\s*\\[([^\\]]+)\\]\\s*(.*)$") | .[3]) |  # Group by message
  map({timestamp: .[0] | match("^\\[([^\\]]+)\\]")?.[1], level: .[0] | match("\\[([^\\]]+)\\]")?.[1], message: .[0] | match("\\[([^\\]]+)\\]\\s*\\[([^\\]]+)\\]\\s*(.*)$")?.[3], count: length}) |
  {errors: map(select(.level == "ERROR")), warnings: map(select(.level == "WARN")), total_unique: length}'
```

### 2. Vector Configuration (Streamlined)
Keep Vector simple for initial parsing:
- Input: `logs/installer.log`, `logs/security-reports/*.txt`
- Transform: Extract timestamp, level, message using regex
- Output: NDJSON to `logs/parsed.ndjson` for potential toon processing

### 3. Evidence Bundle Generation
- **Runner Script**: `maintenance/extract-evidence.sh`
- **Execution**: Called after maintenance scripts
- **Bundle Structure**:
```json
{
  "timestamp": "2026-04-16T15:31:33Z",
  "hostname": "mzapan",
  "evidence": {
    "security": { /* from security-audit.sh output */ },
    "installer": { /* from installer.log last run */ },
    "maintenance": { /* from weekly-check.sh output */ },
    "updates": { /* from update-check-*.json */ }
  },
  "summary": {
    "critical_issues": 0,
    "errors_count": 5,
    "warnings_count": 12,
    "blockers": ["sudo_required", "tool_missing"]
  }
}
```

### 4. Integration Points
- **security-audit.sh**: Append `extract_security_evidence "$REPORT_FILE" >> evidence-bundle.json`
- **weekly-check.sh**: Run full evidence extraction
- **Storage**: `logs/evidence-bundle-$(date +%Y%m%d-%H%M%S).json`
- **AI Access**: Direct file reads or API endpoint

### 5. Quality Assurance
- **Test Cases**: Various failure scenarios (sudo missing, tools unavailable, network issues)
- **Validation**: Compare extracted evidence vs. raw logs for accuracy
- **Size Metrics**: Track bundle size vs. original logs (target: <10% of original size)
- **Completeness**: Ensure all blockers and critical issues captured
