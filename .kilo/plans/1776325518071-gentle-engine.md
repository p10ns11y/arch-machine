# Refactor Security Audit Script

## Overview
Refactor `maintenance/security-audit.sh` to improve code cleanliness, handle edge cases (especially sudo requirements), provide better reporting with summaries and links to full logs, and ensure it works gracefully when tools require elevated privileges.

## Current Issues
1. **Sudo Dependencies**: Many checks (Lynis, ClamAV, rootkit tools, user accounts) require sudo but are skipped entirely when not available, providing no useful output.
2. **Incomplete Reporting**: Locked user accounts (28 total) are not listed in reports; only unlocked accounts shown. Report lacks details on locked accounts.
3. **Verbose Output**: Report includes unnecessary details in console; should summarize and point to logs for full details.
4. **Edge Cases**: Poor handling of missing tools, timeouts, or partial successes.
5. **Code Structure**: Functions are long; some repetition; tool checks scattered.

## Goals
- **Clean Code**: Modular functions, clear flow, remove redundancy, consistent error handling.
- **Edge Case Handling**: Run alternative checks when sudo unavailable (e.g., getent passwd for basic user info).
- **Improved Reporting**: Summarize key findings in console; full details in log files. List locked accounts in report.
- **Reliability**: Better timeout handling, fallback options, informative warnings instead of silent skips.

## Plan Steps

### 1. Analyze Dependencies and Alternatives
- Identify sudo-required vs. non-sudo tools/checks.
- Research alternatives for sudo-dependent checks:
  - User accounts: Use `getent passwd` for basic info without sudo; note limitations.
  - Lynis: Check if user-mode audit is possible (limited but better than nothing).
  - Rootkit checks: Some tools might run partially without sudo.
- Confirm which tools can run effectively without sudo.

### 2. Restructure Script
- **Modularize Functions**: Break large functions into smaller, focused ones (e.g., separate tool installation, audit execution, reporting).
- **Consistent Error Handling**: Use try/catch-like patterns with `||` and `&&`; log errors consistently.
- **Configuration**: Move hardcoded paths/configs to variables at top.
- **Flow Improvement**: Main function calls in logical order; early exits for critical failures.

### 3. Enhance Edge Case Handling
- **Sudo Checks**: Use a helper function to check sudo availability; provide fallbacks.
- **Tool Availability**: For each tool, define fallback behavior when unavailable.
- **Timeouts**: Increase timeouts where appropriate; handle timeouts gracefully.
- **Partial Results**: Collect and report partial successes (e.g., partial ClamAV scans).

### 4. Improve Reporting
- **Summary in Console**: Key metrics and warnings in terminal output.
- **Detailed Logs**: Full outputs in report files; reference in summary.
- **User Accounts**: List both unlocked and locked accounts in report (or note why not possible).
- **Artifacts**: Ensure SBOM and reports are generated even on partial runs.
- **Recommendations**: Tailor based on what was actually run (e.g., "Run with sudo for full audit").

### 5. Code Quality Improvements
- **Readability**: Clear function names, comments only where needed (remove tool reference comments if not essential).
- **DRY Principle**: Extract common patterns (e.g., sudo checks, report appending).
- **Testing**: Add dry-run support for all sections; verify fallbacks work.

### 6. Implementation Order
1. Helper functions (sudo check, tool check, report helpers).
2. Refactor audit functions one by one, adding fallbacks.
3. Update main function and report generation.
4. Test with and without sudo to ensure graceful degradation.

### 7. Verification
- Run script without sudo: Should provide basic info, warnings about limitations.
- Run with sudo: Full audit as before.
- Check reports: Summaries in console, details in files.
- Edge cases: Missing tools, timeouts, partial failures.

## Risks
- Over-reliance on fallbacks might give false sense of security.
- Ensure fallbacks don't hide real issues.
- Maintain backward compatibility for existing usage.
