# Integrate Vector for AI-Optimized Log ETL

## Overview
Integrate Datadog Vector into the arch-machine maintenance system to create an AI-optimized log ETL pipeline. Process large text logs from maintenance scripts, analyze content, remove sensitive information, and generate high-quality, token-efficient samples (velocity, variety, volume) so AI agents can understand system state without excessive token consumption.

## Goals
- **Log Analysis & Curation**: Analyze unstructured text logs, extract key insights, remove sensitive data (passwords, keys, PII).
- **Token Efficiency**: Produce condensed, high-signal JSON summaries rather than raw logs.
- **AI-Friendly Format**: Structured JSON with velocity (frequency metrics), variety (diverse event types), volume (aggregated counts) for AI context.
- **"toon -e" Integration**: Use toon tool to evaluate/optimize JSON output for AI consumption.
- **Maintenance Integration**: Seamless processing without disrupting existing workflows.

## Current Log Data Structure
- **Text Logs** (`logs/installer.log`): Timestamped entries like `[2026-04-16 11:09:43] [INFO] Section header` or `[ERROR] Failed to install chkrootkit`
- **Security Reports** (`logs/security-reports/`): Structured text reports with sections (ROOTKIT DETECTION REPORT, USER ACCOUNTS REPORT) containing metrics and lists
- **Existing JSON** (`logs/update-check-20260410.json`): Already structured JSON with timestamp, hostname, system_packages, tool_updates, security_updates, summary
- **Log Challenges**:
  - Verbose text with repetitive sections and emojis
  - Mixed structured/unstructured data
  - Sensitive info potentially in logs (though not seen in samples)
  - Large volumes (installer.log has 5000+ lines)
  - Token inefficiency for AI: full lists vs. summaries (e.g., 30 user accounts listed individually)

## Vector ETL Strategy

### 1. Input Sources
- **File Sources**: Monitor `logs/` and `logs/security-reports/` directories for new log files.
- **Real-time Processing**: Watch for log writes during maintenance execution.

### 2. Transform Pipeline
- **Parsing Transforms**:
  - Regex for timestamps: `[2026-04-16 13:22:02]` → ISO format
  - Level extraction: `[INFO]`, `[WARN]`, `[ERROR]`
  - Content grok patterns for structured data (user counts, security findings)
- **Enrichment Transforms**:
  - Add metadata: script name, hostname, execution context
  - Aggregate metrics: count occurrences, calculate rates
- **Filtering & Sanitization**:
  - Remove sensitive patterns (passwords, keys, personal data)
  - Deduplicate repetitive entries
  - Filter low-value logs (debug traces, success confirmations)

### 3. Output Optimization
- **Structured JSON**: Emit condensed summaries with:
  ```json
  {
    "timestamp": "2026-04-16T13:22:02Z",
    "script": "security-audit.sh",
    "summary": {
      "velocity": {"events_per_minute": 15.2},
      "variety": {"unique_levels": ["INFO", "WARN"], "event_types": ["user_check", "service_scan"]},
      "volume": {"total_lines": 234, "warnings": 2, "critical": 0}
    },
    "key_insights": {
      "user_accounts": {"total": 30, "unlocked": 2, "locked": 28},
      "services": {"listening": 57, "suspicious": 0},
      "security_status": "partial_audit_no_sudo"
    },
    "ai_context": "System audit completed with limited sudo access. 28 locked accounts detected. No critical security issues found."
  }
  ```
- **Token-Efficient Sampling**: Prioritize high-impact events, aggregate similar logs, provide executive summaries.

### 4. "toon -e" Processing
- **Evaluation Step**: Pipe JSON output to `toon -e` for AI-optimized refinement.
- **Potential Actions**: Further compression, relevance scoring, context enrichment, token count optimization.

### 4. Output Optimization

### 5. Integration & Automation

- Measure token reduction vs. raw logs
