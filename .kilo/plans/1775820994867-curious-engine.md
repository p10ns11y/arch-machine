# Extension Plan: Automated Tool Installation and Maintenance System

## Overview
Extend the existing installer repository to include an organized, modular tool installation system and automated weekly maintenance checks for keeping the development environment up-to-date and secure.

## Current State Analysis
The repository contains three main scripts:
- `basic_setup.sh`: Initial ML/AI development setup with ROCm, mise, uv, conda environments
- `secure-fortress-phase0-simple.sh`: Security hardening with k3s, Cilium, Tetragon, encrypted storage
- `config/setup-*-ssh-gpg.sh`: SSH/GPG key setup scripts

Current limitations:
- Manual execution only
- No ongoing maintenance system
- Tools installed as monolithic scripts
- No version tracking or update notifications
- No automated security patching

## Goals
1. **Modular Tool Installation**: Break down tool installation into organized, configurable modules
2. **Automated Maintenance**: Weekly automated checks for updates, security patches, and new versions
3. **Version Management**: Track installed versions and notify about available updates
4. **Security Monitoring**: Regular security audits and patch management
5. **Logging & Notifications**: Comprehensive logging and optional notifications for maintenance activities

## Implementation Plan

### Phase 1: Modular Installation System
1. **Create Tool Categories**:
   - `modules/system/`: Base system tools (pacman packages, services)
   - `modules/development/`: Development tools (mise, uv, editors, git)
   - `modules/ml-ai/`: ML/AI specific tools (ROCm, PyTorch, conda environments)
   - `modules/security/`: Security tools (k3s, Cilium, Tetragon, encryption)
   - `modules/productivity/`: Additional productivity tools

2. **Configuration-Driven Installation**:
   - `config/tools.yaml`: Centralized configuration file defining tools, versions, and installation methods
   - `config/profiles/`: Profile configurations (minimal, full, ml-dev, security-dev)
   - Each module reads from config to determine what to install

3. **Installation Framework**:
   - `lib/installer.sh`: Core installation functions (package install, version checking, dependency resolution)
   - `lib/validator.sh`: Post-installation validation functions
   - `install.sh`: Main installer that orchestrates module installation based on profile

### Phase 2: Automated Maintenance System
1. **Maintenance Script** (`maintenance/weekly-check.sh`):
   - System package updates (`pacman -Syu`)
   - Tool version checks and updates (mise, uv, conda)
   - Security vulnerability scanning
   - Disk space monitoring
   - Log rotation and cleanup
   - Health checks for services (docker, k3s, etc.)

2. **Update Management**:
   - `maintenance/check-updates.sh`: Check for new versions of tools without installing
   - `maintenance/apply-updates.sh`: Apply approved updates
   - Version tracking database (JSON file) to record installed versions

3. **Security Monitoring**:
   - `maintenance/security-audit.sh`: Run security checks (lynis, chkrootkit, etc.)
   - `maintenance/patch-manager.sh`: Manage security patches
   - Integration with Arch security advisories

### Phase 3: Automation and Scheduling
1. **Systemd Timer/Service**:
   - `systemd/maintenance.service`: Runs maintenance script
   - `systemd/maintenance.timer`: Weekly timer (configurable)
   - User notification on maintenance completion

2. **Cron Alternative**:
   - Fallback cron job for systems without systemd timers
   - `maintenance/cron-setup.sh`: Install cron job

3. **Notification System**:
   - Email notifications (optional)
   - Desktop notifications
   - Log file generation with maintenance reports

### Phase 4: Enhanced Features
1. **Backup Integration**:
   - Pre-maintenance backups of critical configs
   - Rollback capability for failed updates

2. **Dependency Management**:
   - Automatic dependency resolution
   - Conflict detection and resolution

3. **Reporting**:
   - Weekly maintenance reports
   - Version change logs
   - Security incident tracking

## Configuration Example (tools.yaml)
```yaml
tools:
  system:
    packages:
      - name: base-devel
        critical: true
      - name: git
        min_version: "2.40.0"
    
  development:

      versions:
        python: ["3.12", "3.13", "3.14"]
        node: ["22", "lts"]
```

## Maintenance Workflow
1. **Weekly Schedule**: Run maintenance check every Monday at 2 AM
2. **Pre-flight Checks**: Verify system health, backup configs
3. **Update Process**:
   - Check for package updates
   - Update tool versions
   - Apply security patches
   - Validate installations
4. **Reporting**: Generate report with changes, issues, recommendations
5. **Notification**: Alert user of critical updates or issues

## Risk Mitigation
- **Testing**: All scripts include dry-run modes
- **Rollback**: Ability to revert changes
- **Validation**: Post-update health checks
- **User Consent**: Interactive mode for major changes
- **Logging**: Comprehensive logging for troubleshooting

## Success Metrics
- Reduced manual maintenance time
- Automated security patching
- Consistent tool versions across machines
- Proactive issue detection
- Clear maintenance reporting

## Dependencies
- yq or jq for YAML/JSON processing
- curl for version checking
- systemd or cron for scheduling
- Optional: notify-send for desktop notifications

## Migration Path
1. Preserve existing scripts as legacy
2. Create migration script to convert current setups
3. Gradual rollout with backward compatibility
4. Documentation for transitioning users
