# Plan: Fix and Refactor Arch-Machine Installer System

## Overview
The current installer system has several critical issues that prevent proper functionality:

1. **YAML parsing inconsistencies** - Mixed path formats causing failures
2. **Missing profile validation** - No `--validate` option despite README claiming it exists
3. **Broken module loading** - Modules not finding correct installation functions
4. **Profile customization not applied** - Custom settings ignored during installation
5. **Inconsistent logging** - Scripts calling log() incorrectly
6. **Missing features** - Several README-promised features not implemented

## Current Issues Analysis

### YAML Parsing Problems
- `yaml_get` function uses inconsistent path formats
- Some calls use `tools.system.packages[]` (missing leading dot)
- Others expect different formats
- yq syntax not standardized

### Profile Processing Issues
- `get_modules_to_install()` fails silently when YAML parsing fails
- No validation that profile files exist or are valid
- Customizations section completely ignored
- No feedback on what modules would be installed

### Module System Problems
- Modules try to source non-existent lib files
- Installation functions not found due to wrong naming
- No fallback when modules fail to load

### Missing Features
- `--validate` option not implemented
- Profile validation missing
- System health checks incomplete
- Migration tool not properly integrated

## Implementation Plan

### Phase 1: Core Infrastructure Fixes

1. **Standardize YAML Parsing**
   - Update `yaml_get()` to normalize paths (auto-add leading dot if missing)

2. **Fix Profile Processing**
   - Add proper error handling in `get_modules_to_install()`
   - Implement profile validation function

3. **Module System Refactor**
