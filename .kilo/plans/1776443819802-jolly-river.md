# Plan: Cleanup lib/validator.sh - Comment Out Advanced Use Cases

## Goal
Clean up `lib/validator.sh` by organizing commented-out code for advanced use cases (Kubernetes, Cilium, Tetragon validations) and implement a mechanism to enable them via flags or profiles, keeping the main file focused on basic validations.

## Current State Analysis
- `lib/validator.sh` contains basic validation functions (packages, services, commands, etc.)
- Advanced validation functions for Kubernetes, Cilium, and Tetragon are already commented out
- `run_validation()` has some commented calls to advanced validations
- Code is functional but cluttered with commented blocks

## Proposed Changes

### 1. Extract Advanced Validations
- Create new file: `lib/validator_advanced.sh`
- Move commented functions (`validate_kubernetes`, `validate_cilium`, `validate_tetragon`) to this file
- Update exports in both files appropriately

### 2. Clean Up Main Validator
- Remove commented function definitions from `lib/validator.sh`
- Remove commented validation calls from `run_validation()`
- Add clean comments referencing advanced validations

### 3. Add Enable Mechanism
Use a new profile "secure-infra" to enable advanced validations.

- Add new profile "secure-infra" to `run_validation()` case
- Include Kubernetes, Cilium, and Tetragon validations in this profile
- Profile-based approach, consistent with existing structure

## Implementation Steps
1. Create `lib/validator_advanced.sh` with extracted functions (`validate_kubernetes`, `validate_cilium`, `validate_tetragon`)
2. Update `lib/validator.sh` to remove commented code and function definitions
3. Add "secure-infra" profile case in `run_validation()` to include advanced validations
4. Update function exports in both files
5. Update any references (e.g., in main installer if needed)
6. Test basic validations and new "secure-infra" profile

## User Decisions
- Use new profile "secure-infra" for advanced validations
- Keep advanced validations separate from existing profiles
- No additional code to comment out for advanced cases

## Risks
- Breaking existing validation if references are missed
- Advanced validations may require additional dependencies (kubectl, etc.)

## Benefits
- Cleaner main validator file
- Advanced features preserved for future use
- Modular design for maintenance
