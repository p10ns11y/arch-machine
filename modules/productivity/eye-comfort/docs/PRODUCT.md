# Product

## Register

product

## Users

Single operator on a Linux laptop (Omarchy/Hyprland): long coding and reading sessions, evenings often dark-room, days under mixed indoor light. Primary surfaces: terminal (Ghostty), editor (nvim), file manager (Yazi), desktop wallpaper. Goal is frictionless focus — the chrome should disappear into the task.

## Product Purpose

**Eye-comfort** is a circadian, vision-science theme system for the whole desktop: dawn / day / dusk / night Omarchy packages applied on a seven-phase schedule, with matching wallpapers, terminal, nvim, and Yazi. Success = less eye strain, warm low-blue nights, soft day cream without pure white glare, transitional dawn/dusk that feel like real light, and one SoT palette (`PALETTE.md` + OKLCH phases) that never fights itself across hosts.

## Brand Personality

Calm · Warm · Precise  
Quiet craft over spectacle. Museum lighting, not neon. Scientific restraint with material warmth (umber, parchment, sage, clay).

## Anti-references

- Cool blue-black “cyber” desktops (e.g. ethereal `#060B1E`, Tokyo Night blues at night)
- Pure black / pure white extremes
- High-saturation rainbow syntax noise
- Generic AI “cream SaaS” marketing aesthetic used as decoration rather than circadian light mode
- Busy wallpapers that fight floating windows
- Helix as a required surface (nvim is enough)

## Design Principles

1. **Eye comfort first, then circadian** — luminance and contrast before temperature tricks.
2. **One SoT, thin mirrors** — apps only project locked roles; no dual palettes.
3. **Restrained color** — low–medium saturation; raise sat only for error/warning.
4. **Wallpaper is stage, not star** — calm fields and negative space so windows read first.
5. **Warm dark at night, soft cream by day, honest transitions** — dawn/dusk earn their own packages; schedule-backed, not sensor theater.

## Accessibility & Inclusion

- Body text contrast ≥ 4.5:1 (WCAG AA) on terminal/editor fg/bg.
- No pure black/white as primary bg/fg.
- Semantic color only (error/warning); don’t encode status in blue-only cues.
- Optional hyprsunset CCT is assistive, not required; must stay easy to disable.
